# WebRTC V2 周结果目录

这里保存 Week 1～10 **实际完成后**的脱敏结果，不再预先复制总体计划。唯一任务规划来源是
[WebRTC 双客户端优先研发总计划](../../../roadmap/webrtc_v2_project_plan.md)。

## 目录用途

| 目录 | 对应阶段 |
| --- | --- |
| `week01/`～`week02/` | M0 学习、环境和手工信令基线 |
| `week03/` | H.264 契约、解码入口与 RTMP 兼容 |
| `week04/` | 对称 endpoint、固定 MP4 publisher 与双 Offer 角色 |
| `week05/` | 同一客户端 viewer 与媒体回环 |
| `week06/`～`week07/` | 社团 LAN 包与跨公网 Direct/Needs Relay |
| `week08/` | 正式客户端一次性接收、状态和安全集成 |
| `week09/`～`week10/` | 摄像头、多路、故障、性能和 Beta 资格 |

## 完成后允许的文件

- `summary.md`：目标、实际完成、未完成、架构影响和下一周入口。
- `test_results.md`：环境、命令、通过/失败、人工场景和脱敏性能结果。
- `testing_guide.md`：仅在需要交给用户执行独立自动/人工流程时创建。
- `known_issues.md`：只在存在可复现且未解决的问题时创建。

尚无正式结果的目录仅用 `.gitkeep` 保持结构；出现第一份正式结果后删除对应 `.gitkeep`。Week 2
已有自动结果且人工门禁仍待补；Week 3 已有契约/解码入口结果；Week 4 已有 publisher/session、
自动测试和资产边界结果；Week 5 已有 viewer 闭环、自动测试和独立测试指南。

## 禁止提交

- 构建目录、测试缓存和大段原始日志；
- Offer/Answer 会话包、完整 SDP、ICE candidate、IP、端口和真实 STUN URL；
- Token、密码、私钥、证书和 `.env` 内容；
- 网络抓包、测试视频、截图原件和二进制发布物；
- 未经验证的能力结论。

大型或敏感现场证据留在仓库忽略目录，只在周结果中记录脱敏摘要、证据位置类别和验证结论。

## 结论用语

周结果必须区分：代码存在、构建成功、自动测试通过、人工链路通过、真实公网通过、ARM 交叉构建
和 ARM 真机通过。任何一类证据都不能替代另一类。
