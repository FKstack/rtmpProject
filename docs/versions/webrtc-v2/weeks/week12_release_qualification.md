# V2 Week 12：性能、跨平台与 Beta 发布门禁

## 本周目标

形成可审计的 Beta 资格结论，明确已通过、失败和仍待真机/公网验证的边界。

## 知识

- 构建成功、交叉构建、QEMU、真机和公网性能是不同证据等级。
- P95 延迟需要固定预热、采样时长、时钟口径和失败门槛。
- 发布包必须审计运行时依赖、许可证、默认网络和敏感内容。

## 实验与资格矩阵

- Windows Debug/Release 全目标、完整 CTest 和停止/退出复验。
- 公网服务器 1/4/8 路、P2P 1/4 路 Direct/Relay：预热后 600 秒采样。
- Windows 便携包在全新目录运行版本、启动、连接和退出 smoke。
- Linux ARM64 RASTER/GLES3 交叉构建、ELF 和动态依赖审计。
- 有真实板时追加 QPA、网络、视频、音频和长期温度/资源测试；没有则保持待验证。

## 开发与文档任务

- 完成运行时 DLL/so、许可证和 WebRTC 第三方通知。
- 扫描源码、Git diff、配置和包，不得含真实端点、凭据、SDP/candidate 或用户状态。
- 更新项目快照、交接、ADR-032、known issues 和 Beta 发布说明。
- 记录 16 路能力结果但不设为发布门槛；不创建正式版本标签。

## 验收

- P2P 受控局域网单路源到呈现 P95 ≤ 200 ms。
- 同区域公网服务器模式 P95 ≤ 300 ms。
- 所有正式组合无无界队列、旧帧、退出残留和未脱敏日志。
- Windows 包依赖完整；ARM 只有真机通过后才能声明 WebRTC ARM 支持。

## 风险与停止条件

- 任一硬门槛失败即保留 Beta/known issue，不通过降低门槛制造“通过”。
- 公网、TURN 或 ARM 环境缺失时只记录“未执行”，不使用模拟结果替代。
- 发现真实 endpoint/Secret 进入 Git 或包时立即停止分发并执行脱敏审计。
