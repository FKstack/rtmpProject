# RtmpMonitor v0.1.0-alpha.1 版本冻结与交付任务清单

> 文档日期：2026-08-09
>
> 目标版本：`v0.1.0-alpha.1`
>
> 目标定位：Windows 开发预览版、ARM Linux 工程预览版
>
> 适用人员：项目维护者、Windows 测试人员、嵌入式二次开发人员
>
> 最近进度：2026-08-10 完成 Phase 0 的版本号与功能冻结项；其余任务仍按未完成处理。

## 1. 发布结论与边界

当前功能已经达到并超过最初的一路 RTMP 播放 MVP，可以在完成本清单的 P0
任务后作为源码开发预览版交给嵌入式开发人员。但目前不能标记为正式 `v1.0`，也
不能直接把工作目录或单个 Debug EXE 作为测试包发送。

本次交付拆成三个相互独立的门槛：

| 交付物 | 当前判断 | 放行条件 |
| --- | --- | --- |
| 源码二次开发包 | 条件允许 | 完成 Phase 0～2，Git 快照干净且文档一致 |
| Windows 解压即用测试包 | 暂不允许 | 完成 Phase 0～4，并通过干净机验证 |
| ARM Linux 可运行发布版 | 暂不允许 | 额外完成 Phase 5 的真实目标板验收 |

发布声明只能使用：

```text
RtmpMonitor v0.1.0-alpha.1
Windows Development Preview
ARM Linux Engineering Preview
```

不得使用“正式版”“生产可用”“ARM 已适配完成”或“全面产品化完成”等表述。

## 8. Phase 5：嵌入式朋友负责的 ARM 真机验收（P1）

### 环境与构建

- [ ] 冻结目标板硬件型号、系统镜像和厂商 SDK/sysroot。
- [ ] 比对目标板 glibc/musl、动态加载器、libstdc++、Qt 和 FFmpeg ABI。
- [ ] 优先在目标板本机构建 SRS；设备资源不足时再使用交叉编译。
- [ ] 分别构建/部署 RASTER 与 GLES3；无可靠 GPU 时使用 RASTER，不强制 OpenGL。
- [ ] 用 `file`、`readelf`、`ldd` 验证架构、解释器、RPATH 和依赖来源。

### 图形与交互

- [ ] 验证实际 QPA 插件：linuxfb、eglfs、Wayland 或 X11。
- [ ] 验证字体、中文、屏幕旋转、分辨率、鼠标/触摸和全屏恢复。
- [ ] GLES3 路径验证真实 Context、Shader、FBO、纹理格式与 context loss。
- [ ] EGLFS 保持单画布全屏，不引入第二个 OpenGL 顶层窗口。

### 摄像头和性能

- [ ] 真实摄像头从 LAN 推流到 ARM SRS，不能只测 `127.0.0.1`。
- [ ] 验证 H.264 profile/level、GOP、SPS/PPS、IDR、时间戳和音频兼容性。
- [ ] 从 1 路开始，按 2/4/8/16 路逐级测试；失败即停止升档。
- [ ] 记录每级 CPU、内存、显示 FPS、帧龄、温度和是否降频。
- [ ] 运行 `scripts/qualify_embedded_device.sh`，输出该设备的
  `recommendedMaxStreams`，不得直接承诺所有板卡支持 16 路。
- [ ] 验证断网、停推、SRS 重启、应用关闭和系统重启后的恢复。
- [ ] 完成目标板长时间稳定性测试，并记录持续时间和最终资源状态。

### 完成标准

- [ ] 形成包含硬件、镜像、依赖、QPA、Renderer、摄像头参数和测试结果的设备档案。
- [ ] ARM 运行版只能对已测试的设备型号、镜像和最大路数作出承诺。
- [ ] Phase 5 未完成前，版本继续标记为 ARM Linux Engineering Preview。
