当前功能已经达到并超过最初的一路 RTMP 播放 MVP，可以在完成本清单的 P0
任务后作为源码开发预览版交给嵌入式开发人员。但目前不能标记为正式 `v1.0`，也
不能直接把工作目录或单个 Debug EXE 作为测试包发送。

| Windows 解压即用测试包 | 暂不允许 | 完成 Phase 0～4，并通过干净机验证 |

#### 5.10.4 崩溃、CRT 对话框、卡死或残留进程的处理

出现任一异常时不要继续计数。先记下失败轮次和时间，在终端 C 执行只读取证：

```powershell
$FailureStamp = Get-Date -Format "yyyyMMdd-HHmmss"
$FailureDir = Join-Path $ManualDir "failures\$FailureStamp"
New-Item -ItemType Directory -Force -Path $FailureDir | Out-Null
Get-CimInstance Win32_Process -Filter "Name='rtmp_monitor.exe'" |
  Select-Object ProcessId, ExecutablePath, CommandLine, CreationDate |
  Format-List | Out-File `
    (Join-Path $FailureDir "process.txt") -Encoding utf8
Get-WinEvent -FilterHashtable @{
    LogName = 'Application'
    StartTime = (Get-Date).AddMinutes(-10)
} -ErrorAction SilentlyContinue |
  Where-Object { $_.ProviderName -match 'Application Error|Windows Error Reporting' `
    -or $_.Message -match 'rtmp_monitor' } |
  Select-Object TimeCreated, Id, ProviderName, LevelDisplayName, Message |
  Format-List | Out-File `
    (Join-Path $FailureDir "windows-application-events.txt") -Encoding utf8
Add-Content -LiteralPath $ResultFile -Encoding UTF8 -Value `
  "- failure ${FailureStamp}: renderer=[填写]; iteration=[填写]; symptom=[填写]"
```

同时用手机或 `Win+Shift+S` 保存 CRT/崩溃对话框画面。然后优先尝试程序正常关闭；
若已经无响应，允许使用 Visual Studio“停止调试”仅作**失败后的清理**，但该轮和本组

### 6.5 必要的人工校验：干净 Windows 安装前置运行时后解压使用

1. 准备一台干净 Windows 11 实机或 VM；确认未安装 Qt、vcpkg、Visual Studio，且
   `where.exe qmake`、`where.exe windeployqt`、`where.exe ffmpeg` 均找不到。若只能
   使用当前开发机，本项保持 `[需要验证]`。
2. 把 ZIP 复制到干净机；不要复制开发机的 DLL 或 PATH。
3. 在干净机 PowerShell 执行：

```powershell
$Zip = Join-Path ([Environment]::GetFolderPath('Desktop')) `
  "RtmpMonitor-0.1.0-alpha.1-windows-x64.zip"
$TestDir = Join-Path $env:TEMP "RtmpMonitor-alpha1-clean-test"
Expand-Archive -LiteralPath $Zip -DestinationPath $TestDir
Get-ChildItem -LiteralPath $TestDir -Recurse
$AppDir = Get-ChildItem -LiteralPath $TestDir -Directory | Select-Object -First 1
Set-Location $AppDir.FullName
```

4. 确认 ZIP 可以完整解压，且文件清单与包内说明一致；解压失败或文件缺失时停止。
5. 检查系统已有 VC++ x64 Runtime；缺少或版本低于 14.41 时，先核对包内
   `vc_redist.x64.exe` 的数字签名发布者为 Microsoft Corporation，再运行一次该
   前置安装器。安装器失败或签名无效时立即停止，不能从其他机器手工复制 DLL。
6. 在资源管理器双击 `rtmp_monitor.exe`：必须启动且没有 DLL 缺失、平台插件或
   MinGW/MSVC 冲突对话框。关闭后再从 PowerShell 执行
   `.\rtmp_monitor.exe --version`，预期 `0.1.0-alpha.1`。
7. 在可由干净机访问的 SRS 上推送 5.4 的 1080p30 流；把示例配置复制为
   `media-server.ini`，只填写该测试 SRS 的 LAN 地址和测试 streamKey，不填写生产
   凭据。双击应用，确认一路播放、全屏、控制栏、截图和正常退出。
8. 关闭应用后执行 `Get-Process rtmp_monitor -ErrorAction SilentlyContinue`，预期无
   输出。删除整个解压目录；删除应成功，且包外不得出现无法解释的持久数据。
9. 把机器/VM 版本、VC++ Runtime 版本、启动方式、播放结果、截图路径和
   卸载结果记录到
   `out/phase3/manual-clean-machine-result.md`，再把脱敏结果交给 Codex审查。
