# V2 Week 09：保存配置与三模式 UI

## 本周目标

让用户能安全选择 RTMP、WebRTC Server 或 P2P，而不会形成 mode/字段错配或保存凭据。

## 知识

- 配置引用与实际 endpoint/credential 分离。
- schema 迁移需要保留原文件，不能在只读加载时静默覆盖。
- UI 表单应由 source variant 决定字段，而不是隐藏无关字段后继续保存。

## 实验

- 使用临时目录加载 v1 RTMP 文件，查看迁移后的内存模型和首次成功保存的 v2 JSON。
- 创建三种档案并检查 JSON 中不存在 Token、密码、SDP 或 candidate。

## 开发任务

- 保存流编辑器增加三种互斥模式和对应字段。
- WHEP 保存服务器配置引用/stream key；P2P 保存信令配置引用/peer ID。
- endpoint、Token 和 TURN 凭据从忽略的本机配置/运行时鉴权获取。
- 列表显示 RTMP/WHEP/P2P 类型和脱敏来源摘要。
- 自动连接遵循默认网络关闭和档案显式选择。

## 验收

- schema v1→v2、未来版本拒绝、损坏文件保留、重复来源和字段校验通过。
- 增删改、自动连接、活动项禁止编辑和 RTMP 旧流程回归通过。
- 保存文件与日志敏感字段扫描为零。

## 风险与停止条件

- 不以一组可空字符串代替 variant。
- 不把完整 WHEP/信令 URL 或 Token 写入档案。
- 未实现的模式必须显示“尚未启用”，不能创建假连接。

## 下周入口

接入协议状态、事件中心和协议无关媒体新鲜度安全语义。
