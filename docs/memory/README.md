# RtmpMonitor 跨会话记忆

本目录保存可审查、可通过 Git 版本管理的项目记忆。它负责让新会话在 OpenViking 不可用时也能恢复主要上下文；OpenViking 只提供补充性的语义召回，不替代仓库事实。

## 文件职责

| 文件 | 职责 |
| --- | --- |
| `/AGENTS.md` | 新会话的强制入口、读取顺序、信息优先级与安全边界。 |
| `project_snapshot.md` | 当前项目目标、技术栈、模块、已验证进度、阻塞与下一步。 |
| `decisions.md` | 只记录重要设计决策，采用轻量 ADR。 |
| `known_issues.md` | 记录可复现或明确未完成的技术问题，并分离事实与推测。 |
| `../project_handoff.md` | 当前会话向下一会话交接的短期状态；该文件保持本地且被 Git 忽略。 |
| `../roadmap/project_plan.md` | 长期路线、正式阶段和验收目标。 |
| `../weeks/` | 已实施阶段的历史记录和验收证据。 |
| `../guides/` | 稳定的架构、开发、构建与测试说明。 |

## 新会话恢复流程

1. 按根目录 `AGENTS.md` 指定的顺序读取文档。
2. 检查 `git status`、当前分支和最近提交。
3. 对当前任务涉及的事实检查代码、CMake 和测试入口。
4. 将 OpenViking 召回视为低优先级线索；若与仓库事实冲突，指出并纠正。
5. 只把经过验证、对未来会话仍有价值的信息写回本目录。

## 日常维护

- Snapshot 应保持精简，目标不超过 300 行；只记录当前事实，不复制周报。
- ADR 只用于影响架构、平台、存储、安全或长期路线的决定。
- Known issues 必须分别写“已验证现象”和“可能原因”。
- Handoff 可以包含当前会话操作顺序，但不要取代 Snapshot。
- 路线变化写入 roadmap；一次性命令输出和长日志留在被忽略的本地目录。

## OpenViking 边界

- Windows 原生 Codex 是当前唯一插件客户端；WSL2 只运行 OpenViking Server。
- 项目使用工作区派生身份，并将召回范围限制为当前 actor；其他仓库不得复用本项目 peer。
- Windows 与 WSL 路径不是同一字符串。未来若启用 WSL Codex，必须把 WSL 工作区显式映射到已验证的 Windows peer，不能同时产生第二份项目身份。
- 用户通用偏好属于全局记忆；项目架构、Bug、服务器地址和任务进度必须限制在项目 peer。
- 真实 `ov.conf`、`ovcli.conf`、数据库、日志、插件状态和凭据均为本机数据，不进入 Git。

## 禁止内容

API Key、Token、密码、私钥、`.env` 内容、完整鉴权 RTMP URL、大段源码、大量原始日志、临时构建产物和未经验证的猜测不得进入长期记忆。
